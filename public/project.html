How to use AIOrc

Multi-agent workflow compiler over MCP — getting started guide.

  1. 1
    Define agents — In Dashboard → Agents. Each agent is a Markdown prompt that the model executes as a step of the flow.
  2. 2
    Build the flow — On this page (Flow Builder). Drag agents from the left panel and connect them. Branch with conditions on the edges; fork with Parallel; iterate with back-edges.
  3. 3
    Save — The flow is validated (single Start, valid agent references, well-formed Parallel forks). Cycles are legal — a back-edge is a loop. If it passes, it is persisted; if not, errors are shown inline.
  4. 4
    Copy the MCP key and configure the target project (see next tab).
  5. 5
    Done — Claude calls workflow.start (verified mode — the server hands it one step at a time and validates every transition) or workflow (compiled mode — the whole flow in one prompt).

1. .mcp.json at the root of the target project

Tells the Claude client how to connect to the AIOrc server.

## AIOrc — Mandatory rule If the AIOrc `workflow` tool is available in this context, ALWAYS call it before responding to any technical task (design, implementation, review, planning, testing). NEVER respond with a direct solution without first calling the `workflow` tool. Execute the steps of the compiled flow in order, without skipping any or using your own judgment to modify them.
Replace /absolute/path/to/AIOrc/mcp-bridge.js with the real path and key-XX... with the project API key.

Decision, Gate and Loop are not separate node types — they are patterns built from plain agent nodes plus edges with conditions, priorities and back-edges. The only structural nodes besides Start/End are Parallel forks, whose branches ALL execute.

◇ Decision — branch by content

Pattern: an agent followed by several outgoing edges with natural-language conditions. Edges are evaluated by ascending priority and a single transition is taken; an edge without condition acts as the fallback.

Example conditions: "intent == 'bug'", "the agent determines that it needs more context".

⛔ Gate — mandatory verdict

Pattern: the agent emits a literal verdict (PASS / FAIL / score ≥ X) and its outgoing edges carry conditions matching that verdict. Same structure as a branch — the verdict text is the condition.

↻ Loop — iteration with cap

Pattern: an edge pointing back to a previous agent (back-edge). Cycles are legal by construction; each agent carries max_invocations (default 10, max 50) which caps the repetition. In verified mode the server enforces the cap itself.

The patterns combine freely (loops inside branches, gates after forks). In compiled mode the target model honors conditions and caps from the instructions; in verified mode (workflow.start / workflow.next) the server validates every transition against the graph and enforces the caps itself.
